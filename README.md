# Rubik's Cube tutorial — [rubiks.coality.net](https://rubiks.coality.net)

A complete beginner-to-CFOP tutorial in three languages:
[Français](https://rubiks.coality.net/) ·
[English](https://rubiks.coality.net/en/) ·
[Bisaya](https://rubiks.coality.net/bis/)

Static MkDocs Material site served by Apache. Nothing runs: the site is a
folder of HTML files.

## What makes it different

Diagrams and algorithms are **computed and verified by a cube engine**, not
copied from elsewhere. A diagram cannot contradict the algorithm it
illustrates, an arrow cannot point the wrong way, and the algorithm lists are
*proven* complete. The build fails otherwise.

It already caught a real error: step 2 said "repeat `R' D' R D` 2 or 4 times",
when the sequence swaps two corners — an even count returns the corner to where
it started. It takes 1, 3 or 5.

## Build

Requires Python 3 (stdlib only) and Docker.

    ./build.sh

Apache serves `site/` immediately. The script stops at the first failure:

| Step | Checks |
|---|---|
| 1 | 30 engine self-tests, 108 3D-rendering self-tests |
| 2 | every algorithm valid, 57 OLL + 21 PLL proven complete |
| 3 | generates diagrams and reference pages for the 3 languages |
| 4 | 1008 content checks across the 3 languages |
| 5 | three `mkdocs build --strict` |
| 6 | hreflang, meta descriptions, robots.txt, sitemap index |

## Languages

No i18n plugin: one config and one source folder per language, three builds
into the same `site/`.

| Language | Config | Sources | Output | URL |
|---|---|---|---|---|
| fr | `mkdocs.yml` | `docs/` | `site/` | `/` |
| en | `mkdocs.en.yml` | `docs-en/` | `site/en/` | `/en/` |
| bis | `mkdocs.bis.yml` | `docs-bis/` | `site/bis/` | `/bis/` |

French must be built **first**: MkDocs cleans its `site_dir`, and the root
build would otherwise wipe `site/en` and `site/bis`.

Generated labels (diagram titles, case names, reference-page intros) live in
`data/i18n.json`, `data/names.<lang>.json` and `data/intros/<lang>/`, not in
the `.md` files.

## Hand-written vs generated

| Hand-written | Generated by `./build.sh` |
|---|---|
| `docs*/**.md` (except opposite) | `docs/avance/*.md`, `docs-{en,bis}/advanced/*.md` |
| `data/oll.json`, `data/pll.json` | `docs*/assets/cubes/*.svg` |
| `data/i18n.json`, `data/names.*.json`, `data/intros/` | `data/f2l_raw.json` |
| `mkdocs*.yml`, `docs/assets/extra.css` | |

Generated files are not committed — run `./build.sh` after cloning.

To change an OLL or PLL algorithm, edit `data/oll.json` / `data/pll.json`: the
diagram is re-rendered from the algorithm, so the two cannot diverge.

## Tools

| File | Role |
|---|---|
| `tools/cube.py` | 3×3 engine, geometric model (position, normal) |
| `tools/render.py` | SVG: unfolded net, top view, PLL arrows |
| `tools/render3d.py` | SVG: isometric view, piece paths, move direction |
| `tools/check_algs.py` | Validates every algorithm, proves list completeness |
| `tools/check_content.py` | Verifies what the pages claim, in all 3 languages |
| `tools/f2l_search.py` | Exhaustive search for the 41 F2L algorithms |
| `tools/build.py` | Generates diagrams and reference pages |
| `tools/seo.py` | hreflang, meta, robots.txt, sitemap index |

## How verification works

- Every algorithm must leave the first two layers intact.
- There are exactly 57 OLL and 21 PLL classes up to AUF; the entries produce
  that many distinct signatures, so none is missing or duplicated.
- The 41 F2L algorithms are found by iterative-deepening search over `<R,U,F>`,
  so each is the shortest possible.
- Diagrams are rendered from the algorithms themselves.
- 3D arrows come from the engine: label each facelet with its origin, apply the
  algorithm, read where it landed. Rotation direction is checked face by face.

## Deployment

`deploy/rubiks.coality.net.conf` is the Apache vhost; `install.sh` does the full
install (move to `/opt`, vhost, certbot).

To move the site to another domain, in one command:

    sudo ./deploy-domain.sh newdomain.example

It checks DNS, installs the vhost, gets the certificate, 301-redirects the old
domain (both :80 and :443), rewrites the sources, rebuilds, and verifies the
result over HTTPS. Apache is reloaded, never restarted.
